# Surf v23 — coherent longshore whitewater transport
Date: 2026-10-23

## User goal
Continue making the existing interactive beach sandbox more logically ocean-like, with natural-looking and smoother surf. The v22 ocean already had layered long swells, 3D breakers and synchronized boats, but the foam texture and flying foam particles didn't share a coastal-current model.

## Design and implementation
- New `src/coastal-flow.js` contains a deterministic bounded alongshore velocity field in normalized ocean UV space and one source for its exact GLSL equivalent. `longshoreSpeed(u,v)` peaks in sheltered shallows, fades on the outer shelf and reaches zero near both lateral world boundaries. A breaking train's local age, `phase`, integrates that speed into a small **forward +z transport** over the course of one visible wave cycle.
- `oceanFragmentShader` now uses `foamTravel(front,uv.y,phase)` to advect foam texture details along the coast for each of the two breaking trains **using its own phase offset**. The main crest location, wave geometry and shorewash position remain unchanged.
- `breakerLipFragmentShader` uses the same GLSL flow formula to advect the detailed bubbly lace texture across each visible 3D breaker.
- `sprayVertexShader` transports the 460 existing GPU particle positions along the coast by up to about 0.24 world units before their current lifecycle completes. `surfSprayPoint` is the CPU counterpart using the same normalized current field and wave phase.
- No new draw calls, particles, geometries, fetches, textures, timers, external content, save-version migrations or DNS changes. The advancing crest does not shift position or cause shore-geometry detachment. Users retain all editor tools and previously saved islands.

## Validation
- **88/88 Node tests PASS**, Vite production build PASS and exact 4-asset Worker packaging/HTTP smoke PASS.
- New tests scan coastal coordinates and phase for bounded, continuous, directional flow; verify particle CPU positions against the surface current and two breaker trains; assert identical shared GLSL functions used by all three foam stages and no per-frame GPU position-buffer mutation.
- Dedicated staging Worker: https://shoreline-sandbox-3d-stage.hikvision.workers.dev/ (HTTP 200 for HTML/app JS/Three.js/CSS).
- Cloudflare Browser Rendering desktop WebGL PASS (255 forest trees, 14 birds, optional frame diagnostics; no fallback). Mobile 390×720 PASS (Tools, wave 1.3 m, foam 160%, Boat selection/close, WebGL initialized).
- Real GPU Edge WebGL2, Intel UHD Graphics 620 / ANGLE Direct3D11, 1280×720: one rolling ~12-second browser frame pacing sample was **51.6 mean FPS, p95 24.5 ms, p99 26.4 ms**, 619 frames, DPR 1, HTTP 200, zero captured JavaScript errors or WebGL fallback. Temporary `ShorelineV23GpuOnce` Windows task was deleted.
- **Do not claim a proven FPS speedup**: prior v22 sample was 56.7 mean FPS on the same class of hardware but not within a controlled identical-load A/B comparison. A difference between two snapshots does not establish regression or improvement either.

## Honest constraints and safe deployment
- Longshore flow is deliberately bounded artistic advection, not a conservation-law-based shallow-water solver; no tidal currents, rip currents, turbulence diffusion, sediment transport or physical boat drift.
- Preserves v22 ocean geometry, tide baseline, saved island JSON and color palette. No UI redesign in v23. Reference video is not pixel-exact; scene remains stylized.
- Preexisting Three.js vendor chunk is ~511 kB minified and produces Vite's warning. This patch does not optimize it.
- Source branch `feat/surf-v23-longshore-foam-transport`, production rollback baseline v22 main merge `6e209ac218bbd2dbda16b4d63673da77bc3e29be`.
- After GitHub merge, deploy only isolated Worker `shoreline-sandbox-3d` at https://beach.qs3d.site/; leave other Workers, subdomains and DNS unchanged.
