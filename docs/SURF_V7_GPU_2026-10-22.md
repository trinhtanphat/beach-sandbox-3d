# Surf v7 — GPU-only breaker and spray animation (2026-10-22)

## Objective
Follow up on a user-reported unconvincing surf experience and persistent performance concerns. Avoid another visual-only shader pass without addressing CPU overhead. Baseline release: merge `3797e9b8b9f228f291ab88f7bf7a2ed647c696a7`.

## Changes
- The 2,010-vertex foam lip is created once from static coastline anchors and per-vertex water-width attributes; the vertex shader now performs all wave motion from `uTime`/`uWave`. There is no `BufferAttribute.needsUpdate` call per frame.
- 460 foam droplets are now drawn with static seeded anchor attributes and a GPU vertex shader for front position, height and lifecycle fade. No per-frame JavaScript trigonometry or streaming position/life buffers.
- Both GPU shaders use the same 0.23 Hz wave phase and lifecycle as the ocean's water/foam GLSL, with a numerically tested JS reference (`lipSample`, `surfSprayPoint`).
- Unchanged: original scene, coral, seabirds, user terrain saves, controls, lighting and sound. No additional APIs, image dependencies or secrets.

## Verification evidence
- `npm run check`: **36/36 tests PASS**, Vite production build PASS.
- Added two runtime-like Node tests that instantiate real Three.js geometry and verify static vertex buffers remain bit-for-bit unchanged over 350 simulated frames while uniforms advance.
- Worker preview bundle built with `scripts/build-preview-worker.mjs`: three static assets, 199,222 bytes.
- Staging Worker update HTTP 200: https://shoreline-sandbox-3d-stage.hikvision.workers.dev/
- Cloudflare Browser Rendering captured actual WebGL scene: curved shoreline, breaker and foam present, no visual disappearance at the chosen frame. Mobile scripted interaction PASS at width 390px: Tool palette opens and Wave height updates to 1.2m without WebGL fallback.
- Reproducible CPU microbenchmark: `node scripts/bench-surf-cpu.mjs`, 300 frames, on Windows 181: legacy per-vertex/per-particle JavaScript recalculation = **284.72 ms** total (~0.9491ms/frame); new per-frame uniform update = **0.26 ms** total (~0.0009ms/frame). This is a **CPU work comparison only**; no claim that overall scene FPS improves by this ratio.
- Hardware GPU test: Local desktop Intel UHD 620 is connected, but launching a separate headless Edge process in remote service context failed with exit code 1002. Hardware FPS and full-motion quality remain **unverified**.

## Known limitations
- Scene still uses procedural wave shaders, not fluid simulation; the displayed whitewater is stylized.
- Vite reports the existing nonblocking >500 KB JavaScript chunk warning.
- Visual acceptance is based on still frames and Node tests; user must judge real motion against reference. The browser rendering service on Cloudflare may report a low software FPS not representative of real user devices.
