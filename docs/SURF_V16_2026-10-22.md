# Beach Sandbox v16 — local frame-pacing diagnostics and fewer UI updates
Date: 2026-10-22

## Purpose
Track render stability for multiple wave cycles without relying on an external headless timing harness that intermittently closes Microsoft Edge. Preserve the existing visual effects, saved islands and controls while reducing redundant per-frame DOM and color changes.

## Changes
- Opt-in diagnostic panel activated exclusively by appending `?perf=1` to the site URL.
- The pure `src/frame-metrics.js` collector measures actual requestAnimationFrame cadence in a rolling 12-second window: mean FPS, 95th- and 99th-percentile frame durations, number of samples and effective device pixel ratio.
- Bounded storage (up to 1,200 frame intervals). Hidden-tab intervals are excluded and reset the window. Invalid or massive pauses above 5 seconds are excluded, but slow visible software-rendering intervals (such as ~1 second) are counted instead of being discarded.
- Values are available only in the local browser page: no telemetry endpoints, localStorage records, cookies, server-side metrics or third-party analytics.
- The panel is absent entirely without the query string. Day/night static color palettes update on actual palette transitions instead of every animation frame. Decorative clock and sun marker update four times a second rather than 60+ times per second, without changing the physics/shaders.
- The isolated Cloudflare deploy delta helper now includes updated CSS and app JS along with HTML, while leaving unchanged Three.js vendor assets in place.

## Limitations
- Three.js vendor JS is still approximately 511 KB minified with an existing non-blocking Vite warning.
- Scene uses procedural stylized waves, not hydrodynamic CFD.
- Single ~12s GPU measurement cannot prove long-run thermal stability or a guaranteed FPS under other hardware/scene settings.
